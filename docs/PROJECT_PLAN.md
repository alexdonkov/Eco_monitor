# PROJECT_PLAN — План на проекта

**Проект:** EcoMonitor — Мониторинг на околната среда
**Екип:** Алекс Донков (Ученик 2), Миро (Ученик 1)
**Продължителност:** 5 седмици

## 1. Технологии

| Слой | Технология | Защо |
|---|---|---|
| Интерфейс | HTML5, CSS3, JavaScript (ES6+ модули) | Изискване; без framework — разбираме всеки ред |
| Карта | Leaflet + OpenStreetMap | Безплатна, отворен лиценз, проста |
| Графики | Chart.js | Препоръчана в заданието |
| База данни | Supabase (PostgreSQL, Auth, RLS) | Изискване |
| Външни данни | Open-Meteo Air Quality API | Безплатно, без ключ, европейски данни (CAMS) |
| Тестове | Vitest | Препоръчан в заданието |
| Хостинг | GitHub Pages | Безплатно, директно от хранилището |
| Организация | GitHub Issues + GitHub Project (Kanban) | Изискване; показва приноса |

Библиотеките за браузъра (Leaflet, Chart.js, supabase-js) се зареждат от CDN — не се инсталира нищо допълнително. Само Vitest се инсталира чрез npm за тестовете.

## 2. Архитектура

```
Браузър (GitHub Pages)
 ├─ index.html, css/, js/
 │   ├─ i18n/        bg.js, en.js, i18n.js      — преводи
 │   ├─ api/         supabase.js, openmeteo.js — достъп до данни
 │   ├─ algorithm/   anomaly.js, trend.js, correlation.js, stats.js — собствен алгоритъм (чисти функции)
 │   ├─ ui/          map.js, charts.js, forms.js, alerts.js
 │   └─ main.js      навигация и инициализация
 │
 ├──► Supabase: Auth + PostgreSQL (RLS защитава данните)
 └──► Open-Meteo API (само четене)
```

Алгоритъмът е в **чисти функции** (без DOM и без мрежа) → лесно се тества с Vitest.

## 6. Правила за работа
- Всяка задача е Issue. Commit съобщенията сочат към Issue: `Добавена форма за измерване (#11)`.
- Всеки работи в свой клон (`feature/...`) и прави Pull Request, който другият преглежда.
- Commits всеки ден-два, малки и ясни — **и двамата**.
- `.env` и ключове никога не се качват. В кода е само публичният `anon` ключ — данните пази RLS.
- Използването на ИИ се записва в AI_USAGE.md и в седмичния отчет.

## 7. Рискове

| Риск | Мярка |
|---|---|
| Open-Meteo не отговаря | Данните се пазят в Supabase; приложението работи и без API |
| Грешни RLS политики → изтичане или блокиране на данни | Тестове с 3 акаунта (гост, член, ръководител) |
| Изоставане | MVP първо; допълнителните функции — само след като основните работят |
| Неравномерен принос | Ясно разпределение по Issues, седмичен преглед |
